# 2GIS Business Parser

Русскоязычное приложение для поиска организаций через официальный API 2ГИС, обработки результатов и экспорта CSV, XLSX и JSON. Монохромный интерфейс, Inter, небольшие контурные иконки Lucide. React / TypeScript / Vite / Tailwind / TanStack Table / Zustand; FastAPI / HTTPX / SQLAlchemy / SQLite / openpyxl.

## Быстрый запуск с Docker

Нужен Docker Desktop (Windows/macOS) или Docker Engine с Compose (Linux). В каталоге проекта:

```sh
docker compose up --build
```

Откройте `http://localhost:8000`. Без ключа приложение показывает подключение. В **Настройки → Открыть деморежим** можно проверить весь цикл на явно обозначенных вымышленных данных. Настоящие данные никогда не подменяются демонстрационными.

Docker-образ собран и запущен; в контейнере проверены HTML/API, демопоиск и XLSX с выбранными колонками. В облачной среде с собственным HTTPS-прокси для сборки потребовалось передать доверенный CA через BuildKit: `docker build --secret id=ca_bundle,src=/etc/ssl/certs/ca-certificates.crt -t parser-by-chatgpt-parser .`. Проверка TLS не отключается. На обычном локальном компьютере используйте команду Compose выше.

## Локально без Docker

Нужны Python 3.12+ и Node.js 22+ (проверено на Python 3.12 и Node.js 24).

```sh
python -m venv .venv
```

Активируйте окружение:

- Windows PowerShell: `.venv\Scripts\Activate.ps1`
- macOS/Linux: `source .venv/bin/activate`

Затем из корня проекта:

```sh
python -m pip install -r backend/requirements.lock
cd frontend
npm ci
npm run build
cd ..
python scripts/run.py
```

Откройте `http://localhost:8000`. Остановка сервера — Ctrl+C. SQLite создаётся в `data/parser.db`; задачи и шаблоны сохраняются после перезапуска. Используйте один процесс Uvicorn, без `--workers`: локальный worker выполняет одну задачу одновременно. Пауза и остановка сохраняют курсор последней обработанной страницы. После перезапуска незавершённые задачи переходят на паузу, продолжение запускается вручную.

Для разработки интерфейса в отдельном терминале: `cd frontend`, затем `npm run dev`. Vite проксирует `/api` на порт 8000. Из корня backend запускается командой `python -m uvicorn backend.app.api:app --reload --no-access-log`.

## Настоящий поиск

1. Получите ключ и согласуйте нужный сценарий использования данных в [кабинете 2ГИС](https://dev.2gis.com/).
2. Введите ключ на странице настроек и нажмите **Проверить подключение**. Диагностика делает отдельные запросы к полям и фильтрам, расходуя квоту API. Ключ из формы хранится только в памяти сервера до перезапуска. Он не сохраняется в браузере, SQLite или исходниках.
3. Для постоянного подключения скопируйте `.env.example` в `.env` и задайте `DGIS_API_KEY`. Защитите файл средствами ОС. Не добавляйте его в Git.
4. Укажите в настройках права хранения и экспорта только в соответствии с вашим договором. Без разрешения на сохранение реальный поиск блокируется. Без разрешения на экспорт блокируется выгрузка.
5. В мастере выберите города из справочника, рубрики и фильтры. Пресеты категорий не содержат жёстких ID: для каждого региона выполняется поиск актуальной точной рубрики. Если название неоднозначно, уточните его через кнопку «Справочник» и уберите неточный пресет.
6. Запустите задачу. Результаты, состояние, ошибки и настройки сохраняются. Таблица поддерживает поиск, фильтр по сайту, сортировку, размер и видимость колонок, выбор строк, удаление и карточки. Экспорт выбранных строк появляется под таблицей.

Нужны HTTPS-доступ к `catalog.api.2gis.com` и разрешения вашего ключа. Полные тексты отзывов не запрашиваются. Диагностика подтверждает наблюдаемые поля, но не доказывает полноту контактов для каждой организации. Отсутствующий контакт обычно остаётся `unknown`. Для условий «сайт есть/нет», «есть рейтинг/отзывы/фотографии» используются серверные параметры API, когда диагностика подтверждает доступ и группа условий позволяет их безопасно применить. В остальных случаях учитываются три состояния данных.

## Возможности первой версии

- Четырёхшаговый мастер, несколько городов, 25 пресетов категорий, собственные категории и справочник, исключение рубрик, ключевые слова, центр и радиус.
- Вложенные группы AND/OR, контакты и домены, диапазоны рейтинга/отзывов, обработка неизвестных значений, настраиваемый Contact Score.
- Пагинация, лимиты записей и запросов, регулируемая частота, три попытки загрузки страницы при временных ошибках с увеличением задержки. Все попытки расходуют лимит задачи.
- Дедупликация по филиалу, организации, телефону, домену или названию/адресу. Без данных для ключа разные филиалы не объединяются.
- История, повтор через копирование настроек, шаблоны поиска и экспорта, пауза/остановка/возобновление.
- Выбор и порядок колонок (перетаскивание и кнопки), заголовки, обязательные поля, предпросмотр, BOM/разделитель/заголовки CSV, ширина/закрепление/автофильтр XLSX, null и доступность полей в JSON, защита CSV/XLSX от формул.

## Ограничения и проверка интеграции

Подробная [матрица возможностей](docs/CAPABILITIES.md) отделяет реализованное от недоступного. Выбор стран/точных границ районов, полигоны, исключаемые зоны, проверка сайтов, дата открытия, расписание как фильтр, полный каталог подкатегорий, сравнение запусков и CRM пока недоступны. Ответы с расписанием и числом филиалов можно отобразить и выгрузить при подтверждённом доступе.

Документация и тарифы на официальных сайтах были недоступны из облачной среды (прокси вернул 403). Поэтому актуальные условия лицензии, глубина выдачи и права ключа требуют проверки с вашим аккаунтом. Реальная интеграция реализована и проверена тестами HTTP-транспорта; живые запросы к 2ГИС без ключа **не проверены**. Ограничение глубины 500 результатов для пары рубрика/город обрабатывается как ошибка с просьбой сузить поиск, чтобы не выдавать неполную выборку за полную.

## Тестирование

Из корня с активным окружением:

```sh
python -m pytest -q
```

Тесты используют отдельную временную БД. Для отдельного живого теста задайте `DGIS_INTEGRATION_KEY` в окружении и выполните `python -m pytest -m integration`. Без ключа он явно пропускается.

Браузерный сценарий: `cd frontend`, `npm run test:e2e`. Требуется Chromium: по умолчанию `/usr/bin/chromium`; на другой ОС задайте `CHROMIUM_PATH` к исполняемому файлу браузера. Тест создаёт временную БД, запускает отдельный сервер на 8010 и проходит демопоиск, карточку, скачивание XLSX и планшетный экран. На macOS/Linux: `CHROMIUM_PATH=/путь/к/браузеру npm run test:e2e`; Windows PowerShell: `$env:CHROMIUM_PATH='C:\путь\chrome.exe'`, затем `npm run test:e2e`.

## Развёртывание и данные

По умолчанию сервер доступен только локально, Compose публикует порт на 127.0.0.1. Для сервера задайте `APP_PASSWORD`, домен в `ALLOWED_HOSTS` и используйте HTTPS reverse proxy. Пароль защищает весь интерфейс и API через HTTP Basic. Это однопользовательский инструмент; учётные записи и командная изоляция не реализованы. Запуск без пароля на публичном интерфейсе не предусмотрен.

Результаты реальных поисков старше `RETENTION_DAYS` удаляются при старте сервера. Выберите срок по договору, контролируйте резервные копии и скачанные файлы. Отдельные задачи и результаты удаляются из интерфейса. Удаление SQLite — только при остановленном сервере и осознанном отказе от всей локальной истории. Демо-задачи не смешиваются с реальными.

SQLite — проверенный путь. Для PostgreSQL можно указать SQLAlchemy URL и установить соответствующий драйвер, но этот режим в текущей версии не проверен.

## Структура

- `backend/app/providers/` — абстракция источника, официальный адаптер и явно отдельный demo.
- `backend/app/models.py`, `normalization.py`, `filters.py`, `deduplication.py` — модели и обработка.
- `backend/app/jobs.py`, `database.py`, `export.py`, `api.py` — сохраняемый worker, SQLite, экспорт и HTTP API.
- `frontend/src/` — React-интерфейс и состояние поиска.
- `backend/tests/`, `frontend/e2e/` — серверные и браузерные проверки.
- API-документация локального сервера: `/docs`.
